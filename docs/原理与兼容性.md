# 原理与兼容性

## 1. 为什么走 Eclipse NLS 而不是改二进制

STM32CubeIDE 1.19.0 的实质是 **Eclipse RCP 应用**（`.eclipseproduct` 记录 `id=com.st.stm32cube.ide.mcu.rcp.product`，基础平台为 Eclipse 2024-06 / 4.32，插件 399 个，其中 ST 自有 82 个）。Eclipse 的界面文字**不写死在代码里**，而是走标准 **NLS（National Language Support）** 机制：每个插件把界面文案放在外部 `.properties` 资源包里，运行时按「区域（locale）」选择加载哪一份。

因此汉化的正确做法与 Proteus 一致：**让程序按中文区域去加载中文资源**，而不是去替换可执行文件里的字符串。这正是 Proteus 汉化利用官方 Qt `.qm` 语言包机制的同构方案。

## 2. Eclipse NLS 的加载规则

### 2.1 资源文件的三种命名

| 形式 | 用途 | 例子 |
|---|---|---|
| `<名>.properties` | 基准（英文） | `.../common/messages.properties` |
| `<名>_<语言>.properties` | 该语言的通用版本 | `messages_zh.properties` |
| `<名>_<语言>_<地区>.properties` | 精确区域版本 | `messages_zh_CN.properties` |
| `OSGI-INF/l10n/bundle*.properties` | `plugin.xml` / 扩展点里 `%key` 的外部化文案 | `bundle_zh.properties` |

Java 的 `ResourceBundle` 在区域 `zh_CN` 下按 **`_zh_CN` → `_zh` → 无后缀** 的顺序回退，且会把找到的更通用的包设为上层「父包」。这带来一个很有用的性质：

> **片段包只需要提供「改动的那些键」**，未提供的键会自动回退到 ST 自带的 `_zh`，再回退到英文。所以本项目可以分批、按插件补齐，不必一次译全，任何时候都不会显示空白或乱码。

### 2.2 片段包（fragment）与宿主（host）

Eclipse 插件基于 OSGi。一个「片段包」通过清单声明挂在某个宿主插件上：

```
Bundle-SymbolicName: com.st.stm32cube.ide.mcu.build.nl_zh
Bundle-Version: 1.0.0
Fragment-Host: com.st.stm32cube.ide.mcu.build
```

片段包的内容会**并入宿主的类加载器**，所以宿主在找 `messages.properties` 时，会先命中片段里的 `messages_zh_CN.properties`。命名习惯上片段包后缀用 `.nl_zh`（Eclipse Babel 亦然）。

清单按 OSGi 规范每行 72 字节折行（本项目生成器已实现，续行以单个空格开头）。

### 2.3 启用中文：`-nl` 参数

Eclipse 启动器的 `-nl <区域>` 参数决定 `osgi.nl`，即整个 IDE 的界面区域。**这是整件事的开关**，必须位于 `-vmargs` 之前（`-vmargs` 之后的内容会传给 JVM，`-nl` 会被忽略）。

本项目两种做法都不动二进制：
- `工具\以中文启动.cmd`：命令行直接传 `-nl zh_CN`，**零文件写入**；
- `工具\安装汉化.ps1`：写入 `stm32cubeide.ini`（有 `.zhbak` 备份，可一键还原）。

## 3. 两层分工

### 3.1 Eclipse / CDT 层 → 用官方 Babel

Eclipse 基金会维护 **Babel** 语言包计划，提供各语言的官方 NLS 片段包。简体中文包（`-zh`）覆盖 `eclipse`（平台 / SWT / JFace / 帮助 / 团队）、`tools.cdt`（C/C++ 工具链）、`technology.egit` / `jgit`、`tools.tm` 等。

- 最新版本为 **R0.20.0（2023-02 发布，对应 Eclipse 2022-12 / 4.26）**，此后无新构建。
- 可行性关键：Babel 片段包的清单只写 `Fragment-Host: org.eclipse.ui` / `org.eclipse.cdt.ui` 等，**不带版本范围**，因此不受宿主版本约束，可以挂到 4.32 上。
- 代价：Eclipse 4.26 之后新增的界面词条没有中文（回退英文）。这是官方包停更造成的，不是本方案的问题。

安装方式：解包后按 `plugins/` + `features/` 放入 `dropins` 的同一命名目录。

### 3.2 ST 自有层 → ST 自带 + 本项目补缺

82 个 `com.st.*` 插件共 1544 条界面文案。实测：

- **25 个插件自带中文**，共 578 条（37.5%）；FreeRTOS、Live Watch、Fault Analyzer、ST-LINK、JLINK、SFR 视图、Debug Launch 等为 100%，SWV 为 80%。
- 这些资源是 ST 随安装包发行的，**此前因为没设 `-nl` 而从未被加载**。
- ST 未译的 966 条由本项目翻译（915 条，94.7%），编译为 38 个 `nl_zh` 片段包。

## 4. 兼容性

| 维度 | 情况 |
|---|---|
| IDE 版本 | 已按 1.19.0（Eclipse 4.32）实测；片段包 `Fragment-Host` 不带版本约束，**同 1.x 系列应通用**，跨大版本需重跑 `导出词条.ps1` 校对键名 |
| 资源编码 | 输出为 ISO-8859-1 + `\uXXXX` 转义（与 Java `Properties` 及 ST 自带文件一致），避免乱码 |
| 回退安全 | 未译键 → ST `_zh` → 英文；片段包缺失或损坏也不影响英文启动 |
| 可还原性 | `stm32cubeide.ini.zhbak` + 删除 `dropins\stm32cubeide-zh` 即完全还原；安装前会检测 IDE 是否在运行 |
| 不触碰 | 不改 `plugins/` 内任何原始 JAR，不改 `configuration/`，不反编译 |
